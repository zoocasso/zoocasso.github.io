    • 担当内容

  2. 02収集
    • 担当内容
      {{f:kisti_farm}}でクローラーを分散して動かし、結果を1台のリモートDBに蓄積する収集環境を構築・運用（2022年11月〜2023年1月）。
      理由
      収集先サイトのブロックを避けるため、分散して動かしました。
      技術
      • Python
      • Selenium
      • BeautifulSoup
      • MySQL
    • 担当内容
      調達庁の公共データポータルAPIの収集器を開発。直接のクローリングは頻繁にブロックされ、法的なリスクもあったため、公式APIでの収集を提案し、2023年6月に発注元（KISTI）と協議して採用されました。Amazonの収集をRainforest APIに移す作業を実装（2024年2〜5月）。
      技術
      • Python
      • REST API
  3. 03保存
    • 担当内容
      収集結果を中央MySQLに蓄積。2023年11月時点の累計は{{f:kisti_rows}}：調達の個別属性4,192万・Danawaのレビュー1,605万・Amazonの商品詳細999万・レビューキーワード788万・調達API 478万・Amazonの商品93万・Danawaの商品42万。
      技術
      • MySQL
      • SQLAlchemy
      • pandas
  4. 04処理
    • 担当内容
      モデル3：NTIS（韓国の国家研究開発情報）の研究課題とNICE（韓国の企業情報データベース）の企業を、キーワードで結ぶマッチング{{f:kisti_match}}（SQL）。モデル4：価格帯ごとのK-meansクラスタリング（クラスタ数はDunn indexで選択）。モデル5：レビューから要求品質のキーワードを抽出する日次バッチ（KeyBERT・Sentence-Transformers・Mecab）。2024年はモデル3.1に対応して、調達庁の価格・属性・納品の統計をSQLで作成。
      技術
      • SQL
      • scikit-learn
      • KeyBERT
      • Sentence-Transformers
      • Mecab
    • 他の担当
      プラットフォームのモデルの一部は、大学の委託研究チーム（成均館大学校、国民大学校）が設計しました。Vision Insideは、それらのモデルが使うデータと提供の層を担当しました。
