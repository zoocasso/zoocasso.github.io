맥락

플랫폼은 공공 R&D 성과를 시장의 상품과 이어 주는 분석 모델 여러 개로 이루어집니다. 경쟁 제품 탐색, 리뷰에서 요구 품질 뽑기, 과제와 기업 매칭 같은 모델입니다. 모델 일부는 대학 위탁연구팀(성균관대, 국민대)이 설계했고, 비전인사이드는 그 모델들이 쓰는 데이터와 서빙 계층을 맡았습니다. 그 데이터 계층(수집·적재·배치·서빙)을 비전인사이드 쪽 데이터 엔지니어 1인으로 맡았습니다.

  • 감리 산출물(운영자 매뉴얼, 초기데이터구축완료보고서) 작성

주요 결정

  1. 서버 한 대 대신 노트북 여러 대로 나눠 수집

    이유
    한곳에서 대량으로 요청하면 수집 대상 사이트에 막히기 때문에, 요청을 여러 기기로 나눠 차단을 피했습니다.
    방법
    크롤러를 {{f:kisti_farm}}에 나눠 돌리고, 결과는 원격 DB 한 곳에 모았습니다 (2022년 11월 ~ 2023년 1월).

  2. 상품 식별자(ASIN) 기준으로 중복 제거

    이유
    같은 상품이 여러 카테고리에 동시에 노출되어 카테고리별로 모으면 겹쳤습니다.
    결과
    Amazon 상품 {{f:kisti_asin}}를 {{f:kisti_asin_dedup}}로 줄였습니다.

  3. 쇼핑몰 직접 크롤링에서 API 수집으로 전환

    이유
    2023년 6월 발주처(KISTI)가 쇼핑몰 직접 크롤링 대신 API로 수집하도록 요구했습니다.
    방법
    조달청 데이터는 2023년 4월부터 공공데이터포털 API로 받고 있었고, Amazon은 Rainforest API로 옮겼습니다 (2023년 7월 선정, 2024년 2~5월 구현).

모델 배치와 서빙

  • 모델 3: NTIS 과제와 NICE 기업을 키워드로 잇는 SQL 매칭, {{f:kisti_match}}
  • 모델 4: 가격대별 K-means 클러스터링. 군집 수 k는 Dunn index로 고름
  • 모델 5: KeyBERT, Sentence-Transformers, Mecab으로 리뷰에서 요구 품질 키워드를 뽑는 일 배치
  • 관리 화면: FastAPI와 Jinja2·Tabulator로 필터, 순차 실행, 통합 검색, 엑셀 다운로드 제공
  • 2024년 모델 3.1 대응: 조달청 가격·속성·납품 통계 SQL

근거와 공개 범위

코드와 데이터는 회사와 발주처 자산이라 공개하지 않습니다. 이 페이지의 숫자는 2023년 11월 코드정의서와 당시 일일업무보고에서 옮겼고, 이력서와 같은 기준 문서에서 관리합니다.
