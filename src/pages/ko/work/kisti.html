주요 결정

수집 방식을 바꾼 이유와 데이터를 정리한 기준입니다.

  1. 쇼핑몰 직접 크롤링에서 API 수집으로 전환

    문제
    2022~2023년 초에는 쇼핑몰을 직접 크롤링했습니다. 크롤러를 {{f:kisti_farm}}에 나눠 돌려도(2022년 11월 ~ 2023년 1월) 수집이 자주 막혀 끊겼고, 직접 크롤링은 법적 위험도 있었습니다.
    제안
    공식 API로 수집하자고 제가 제안했고, 2023년 6월 발주처(KISTI)와 협의해 반영했습니다. API 데이터는 형식이 깨끗해 수집 자동화도 쉬워졌습니다.
    방법
    조달청 데이터는 2023년 4월부터 공공데이터포털 API로 받았고, Amazon은 Rainforest API로 옮겼습니다(2023년 7월 선정, 2024년 2~5월 구현).

  2. 상품 식별자(ASIN) 기준으로 중복 제거

    문제
    같은 상품이 여러 카테고리에 동시에 노출되어, 카테고리별로 모으면 겹쳤습니다.
    결과
    Amazon 상품 {{f:kisti_asin}}를 {{f:kisti_asin_dedup}}로 줄였습니다.

책임 범위

과제 전체가 아니라, 제가 맡은 부분을 분리해 적었습니다.

제가 구축·운영한 것

  • Amazon·다나와 Selenium 크롤러, 조달청 공공데이터포털 API 수집기와 나라장터 크롤링
  • {{f:kisti_farm}}에서 돌리고 원격 DB 1대에 모으는 분산 크롤링 팜, 중복 제거
  • 중앙 MySQL 적재, 2023년 11월 누적 {{f:kisti_rows}}
  • 모델 3·4·5 배치: 과제–기업 매칭 SQL {{f:kisti_match}}, 가격대별 K-means(Dunn index), KeyBERT 리뷰 키워드 일 배치. 2024년 모델 3.1 대응 조달청 통계 SQL
  • FastAPI 서비스와 Jinja2·Tabulator 관리 화면(필터, 순차 실행, 통합 검색, 엑셀 다운로드)
  • Amazon 수집의 Rainforest API 전환 구현 (2024년 2~5월)
  • KISTI 프로토타입(협력사의 모델 1·2, 사내 Java팀의 Spring 웹)을 사내 서버로 이전하고 Docker 실행 환경 구성. 프로토타입 웹 개발에도 참여해 DB·Java Spring·프런트엔드 연동을 함께 맡음
  • 감리 산출물(운영자 매뉴얼, 초기데이터구축완료보고서) 작성, 기술 회의 결과 발표와 데이터·코드 요청 대응

  • 대학 위탁연구팀(성균관대, 국민대) · 플랫폼 모델 일부의 알고리즘 설계
