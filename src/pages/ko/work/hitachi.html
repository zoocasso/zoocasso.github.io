홈/시스템/히타치 수탁연구

개발자 한 명에게 묶여 있던 데이터셋 생성을,
연구원이 직접 돌리는 파이프라인으로

규슈공업대학교 연구실의 히타치 수탁연구에서 지원연구원으로 일합니다. 머신비전 카메라로 AI 학습 데이터를 만드는 코드를 처음부터 다시 써서, 2026년 9~10월 네덜란드 현지 실험실에 배포했습니다.

맥락

과제는 산업용 머신비전 카메라로 촬영한 영상에서 AI 학습 데이터를 만듭니다. 2025년 4월 제가 인계받은 기존 코드는 유지보수할 수 없는 상태였습니다. 처음에는 문제가 생긴 곳만 고쳐 썼지만, 촬영 조건이 바뀔 때마다 다른 곳이 다시 깨졌고, 데이터셋을 만들 때마다 개발자가 옆에 붙어 있어야 했습니다.

증상이 아니라 구조가 문제라고 판단했습니다. 데이터셋 생성이 개발자 한 명에게 묶여 있다는 점이 핵심이었습니다.

주요 결정

다시 쓰기로 한 이유와, 결과가 달라지지 않게 한 방법입니다.

  1. 부분 수정을 멈추고 전체를 다시 작성

    이유
    고칠 때마다 다른 곳이 깨져, 패치를 쌓을수록 데이터셋 생성이 더 개발자에게 묶였습니다.
    방법
    카메라 제어·촬영부터 학습용 데이터셋 전처리까지를 하나의 Python 파이프라인으로 다시 짰습니다.

  2. 기존 결과를 기준값으로 두고 단계적으로 교체

    이유
    전체를 다시 쓰면 결과가 모르는 사이에 달라질 위험이 있었습니다.
    방법
    같은 입력에서 새 코드와 기존 코드의 수치가 일치하는지 비교하며 단계별로 바꿨습니다.

  3. 비개발자가 직접 돌리는 GUI

    이유
    데이터셋을 만드는 사람은 연구원인데, 실행은 개발자만 할 수 있었습니다.
    방법
    PyQt GUI를 만들어 PyInstaller 실행 파일로 배포했습니다. 연구원이 개발 환경 없이 직접 데이터셋을 만듭니다.

  4. 코드보다 설계 의도를 먼저 인계

    이유
    제가 빠져도 과제가 멈추지 않아야 했습니다.
    방법
    후임 2명에게 각 단계를 왜 그렇게 나눴는지부터 공유했고, 현지 하드웨어 구축은 후임이 맡았습니다.

책임 범위

제가 맡은 엔지니어링 범위와, 현장에서 다른 사람이 맡은 부분입니다.

제가 만든 것

  • 카메라 제어·촬영부터 학습용 데이터셋 전처리까지 이어지는 Python 파이프라인 재작성
  • 머신비전 카메라 여러 대의 제어와 촬영 조건 표준화 (Spinnaker SDK, PySpin)
  • 측정·해석 프로그램
  • 비개발자 연구원용 PyQt GUI와 PyInstaller 실행 파일 배포
  • 후임 2명에게 설계 인계, 현지 배포와 시연

다른 사람이 한 것

  • 후임 연구원 · 현지 실험실의 하드웨어 구축
  • 과제 파트너 연구진 · 샘플 준비와 기준 판정
  • 히타치 담당자 · 현장에서 프로그램을 직접 사용

네덜란드 현지 배포 (2026년 9~10월)

  1. 2025.04
    기존 코드 인계유지보수할 수 없는 상태. 부분 수정으로 버티다 전체 재작성을 결정.
  2. 2025.04 이후
    파이프라인과 GUI 재작성기존 결과와 수치를 대조하며 단계별로 교체. 후임 2명에게 설계 인계.
  3. 2026.09 – 10
    현지 실험실 준비우리 연구실과 히타치 직원들이 현지 실험실을 배정받아 함께 일함. 후임이 하드웨어를 구축.
  4. 2026.09 – 10
    실제 데이터 생성과제 파트너 연구진이 샘플과 기준 판정을 준비하면, 측정·해석 프로그램으로 AI 학습 데이터를 만듦. 히타치 담당자들이 직접 사용.
  5. 2026.09 – 10
    과제 파트너 앞에서 시연실무를 맡은 쪽과 과제 파트너 양쪽에서 좋은 평가. 현지 업무는 일본어와 영어로.
