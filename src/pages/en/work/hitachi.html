Context

The project produces AI training data from images taken with industrial machine-vision cameras. The code I inherited in April 2025 could not be maintained. At first I fixed only what broke, but every change in capture conditions broke something else, and every dataset needed a developer sitting next to it.

I concluded the problem was the structure, not the symptoms. The core of it: creating a dataset was tied to one developer.

Key decisions

Why I chose to rewrite, and how I kept the results from changing.

  1. Stop patching and rewrite the whole thing

    Why
    Each fix broke something else, and every patch tied dataset creation more tightly to a developer.
    How
    I rewrote everything from camera control and capture to dataset preprocessing as one Python pipeline.

  2. Replace it step by step against the old results

    Why
    A full rewrite risked changing the results without anyone noticing.
    How
    On the same inputs, I checked that the new code's numbers matched the old code's, and replaced it stage by stage.

  3. A GUI that non-developers run themselves

    Why
    Researchers are the ones who make datasets, but only a developer could run the code.
    How
    I built a PyQt GUI and shipped it as a PyInstaller executable, so researchers create datasets themselves without a development environment.

  4. Hand over the design intent before the code

    Why
    The project had to keep going without me.
    How
    I walked two juniors through why each stage is split the way it is, and a junior built the hardware on site.

Scope

The engineering that was mine, and the parts others handled on site.

What I built

  • Rewrote the Python pipeline that runs from camera control and capture to preprocessing the training dataset
  • Control of several machine-vision cameras and standardized capture settings (Spinnaker SDK, PySpin)
  • The measurement and analysis program
  • A PyQt GUI for non-developer researchers, shipped as a PyInstaller executable
  • Design handover to two juniors, on-site deployment and the demo

  • The project partner's researchers · preparing samples and reference labels
  • Hitachi staff · using the program themselves on site
