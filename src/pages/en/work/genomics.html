Annotating genomic variants
against {{f:bio_ref}} of public references

The system links a person's genomic variants (VCF, chip arrays) to public references and reports disease and trait risk, population frequencies, and related drugs and herbal medicines. The analysis algorithm was designed at the company with my team lead; I implemented and deployed the pipeline, backend and frontend. It was an international collaboration with Kyung Hee University's College of Korean Medicine and a Canadian bio research lab.

Loading and annotation

Too large to load in one go, so it went in piece by piece.

The dbSNP source VCFs alone are 237 GB, and the 1000 Genomes sources are 770 GB. So I split the files by chromosome (sed, split) and loaded them a little at a time, in pandas chunks through SQLAlchemy.

Annotation is a four-stage SQL join that attaches the reference tables one after another: dbSNP and 1000 Genomes on a key of chromosome, position, REF and ALT, the GWAS Catalog on rsID and risk allele, and UniProt on variant ID and allele. Chip input finds its position key in dbSNP by rsID.

What I implemented and deployed

  • Implementing the variant-calling pipeline (FASTQ → BWA → samtools → Picard → GATK → VCF)
  • Handling of customer VCF and genotyping-array input (PyVCF)
  • Loading {{f:bio_ref}} of public references, and four-stage SQL annotation
  • Disease and trait risk scores from GWAS odds ratios, population frequencies, and drug and herbal-medicine information per disease
  • The FastAPI JSON API and the report frontend (user-facing screens)
  • Docker deployment, a Harbor private registry, domain and HTTPS

Deployment and limits

What ran in production, and what stayed an experiment.

  1. Deployed with Harbor and Docker

    How
    I set up a Harbor private registry myself on an Ubuntu production server at Korea IDC (certificate, domain, Let's Encrypt), pushed the images there and deployed with Docker.
    Cleanup
    In September 2023 I removed the web screens and turned the service into a JSON API for the frontend.

  2. Limits

    Score
    Risk is a rule-based score from GWAS odds ratios and betas, not a machine-learning prediction.
    Models
    The LDA and 1D-CNN models linking diseases to herbal medicines stayed prototype experiments.
    Access
    After deployment to the production server it stayed reachable only from internal IPs. It was never launched as a public service.
