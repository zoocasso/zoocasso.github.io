I presented the data and the model results in technical meetings with KISTI researchers, and contributed to winning the KRW 300M main-phase contract.

Context

The platform is a set of analysis models that connect public R&D results to products on the market: finding competing products, mining required quality from reviews, and matching national R&D projects with companies. University teams (Sungkyunkwan University, Kookmin University) designed some of the models, and Vision Inside owned the data and serving layers. I handled that data layer (collection, loading, batches and serving) as the only data engineer on Vision Inside's side.

My part

What I did

  • Selenium crawlers for Amazon and Danawa, collectors for the Public Procurement Service API, and crawling of the national procurement site
  • A crawling farm on several laptops loading into one remote database, with de-duplication
  • Batches for models 3, 4 and 5, a FastAPI service and an admin interface
  • Moving the partner's prototype (models 1–2, a Java/Tomcat web app) to company servers and setting up its Docker runtime
  • Audit deliverables: operator manual and initial data-build report

What others did

  • Algorithm design for some models: university research teams
  • Models 1–2 and the prototype web app: a partner company
  • Meeting minutes and reporting: another colleague

Decisions

  1. From crawling shopping sites to APIs

    Origin
    I proposed collecting through APIs instead of crawling shopping sites, and in June 2023 this was agreed with the client, KISTI, and adopted.
    How
    Procurement data had come from the public data portal API since April 2023. Amazon moved to the Rainforest API (selected in July 2023, built from February to May 2024).

  2. Before the API switch: collection spread over several laptops

    Why
    While shopping sites were still crawled directly (2022 to early 2023), large request volumes from one machine kept interrupting collection, so requests were spread across machines to distribute the load. I then proposed collecting through official APIs instead, which was adopted after discussion with the client (above).
    How
    The crawlers ran on {{f:kisti_farm}} and wrote to one remote database (November 2022 to January 2023).

  3. De-duplication by product ID (ASIN)

    Why
    The same product appeared in several categories, so collecting category by category produced duplicates.
    Result
    {{f:kisti_asin}} Amazon products became {{f:kisti_asin_dedup}}.

Models and serving

  • Model 3: SQL keyword matching between NTIS national R&D projects and NICE company records, {{f:kisti_match}} links
  • Model 4: price-band K-means clustering, with the number of clusters chosen by the Dunn index
  • Model 5: a daily batch that mines required-quality keywords from reviews with KeyBERT, Sentence-Transformers and Mecab
  • Admin interface: FastAPI with Jinja2 and Tabulator for filtering, sequential runs, unified search and Excel export
  • Model 3.1 in 2024: SQL statistics on procurement prices, attributes and deliveries
