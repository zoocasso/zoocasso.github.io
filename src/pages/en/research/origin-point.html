Fixed origin and optimized origin

A 1951 USAF resolution chart reconstructed from 9 × 9 elemental images, panels (a) and (d) of ITC-CSCC 2026 Fig. 6. Compare the edges of the bar groups.

Fixed originOptimized origin

Volumetric computational reconstruction (VCR) builds slices of a 3D scene by shifting elemental images, taken from many viewpoints, by an amount that depends on depth and overlapping them. The images can only move by whole pixels, which causes quantization error and blurs the result.

The 2025 paper reduced that error by optimizing the origin point that the overlap is measured from. But finding the best origin meant reconstructing many times, which was slow.

The 2026 paper computes this origin directly from the camera parameters alone, independent of the image. In the paper's experiments it gave the same origin and the same SSIM as the iterative search, and only the time dropped. That it is the same in every case is not guaranteed.

What VCR is

Method

The loop that reconstructed once per candidate origin became one calculation from the parameters.

Before: iterative search

  1. Acquire elemental images
  2. Pick a candidate origin
  3. Run VCR
  4. Score image quality and go back to step 2

Every candidate needs a full reconstruction, so the cost is high.

Proposed: direct calculation

  1. Acquire elemental images
  2. Enter the camera parameters and depth
  3. Compute the origin with the smallest quantization error from a formula
  4. Run VCR once

Only the parameters are used, not the image, so there is no loop. In the paper's experiments, image quality (SSIM) matched the iterative search.

Code

A Python release of both papers' methods: github.com/zoocasso/origin-point-optimization-vcr

  • Origin calculation (origin.py), VCR (vcr.py), quality metrics and a timing script
  • 21 tests, and 10,000 seeded cases checked against the re-implemented research formula
  • NumPy and OpenCV; CuPy is optional, for the GPU timing. MIT license
